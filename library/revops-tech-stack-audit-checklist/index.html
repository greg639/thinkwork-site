RevOps Tech Stack Audit Checklist

Map every tool that touches your funnel from first-touch to renewal, then flag the overlapping licenses, dead integrations, and data leaks quietly costing you money and corrupting your forecast.

What's inside

  • Full stack inventory table across 14 funnel-stage categories (tool, owner, cost, renewal date, last admin login)
  • Integration health check per connection (sync direction, frequency, 30-day error log, ownership, live end-to-end test)
  • License utilization formula with waste thresholds (below 70% = renegotiate, below 40% = kill candidate)
  • Data field system-of-record matrix for your 10 forecast-critical fields
  • Redundancy detector for tools doing the same job-to-be-done
  • Security & access review (SSO coverage, admin counts, departed-employee check, API key age)
  • Keep / Consolidate / Kill / Renegotiate scoring rubric
  • 90-day action plan table with owner, deadline, and estimated savings per tool
  • Recommended audit cadence — full every 6 months, light pass every quarter, always 60 days before renewal

Purpose: Every tool that touches a lead, a deal, or a dollar between "stranger" and "renewed customer" should earn its place. Run this audit quarterly, or before any budget renewal cycle, to catch overlapping licenses, integrations that quietly died months ago, and the fields that disagree with each other across systems.

Who should run this: RevOps lead, Sales Ops, or the most senior sales/marketing leader if no dedicated RevOps function exists yet. Budget 3–4 hours for a stack of 15–25 tools.

Checklist:

  • Every row has a named business owner (a person who'd notice if it vanished — not "IT")
  • Every row has an actual renewal date pulled from the contract, not guessed
  • You've checked login/usage logs, not asked the vendor rep whether it's "still used"
  • Any tool with no login in 60+ days is flagged for kill review

Step 2 — Integration health check (run per connection)

For every integration between two systems (e.g., MAP → CRM, CRM → CPQ, CPQ → billing):

  • Confirm the sync direction (one-way or bi-directional) matches what the business actually needs
  • Confirm sync frequency (real-time, hourly, nightly batch) — flag anything nightly-batch that feeds a "live" dashboard
  • Pull the integration's error/failure log for the last 30 days — any integration with silent failures gets flagged red
  • Confirm someone owns monitoring this integration (not "it was set up by a consultant who left")
  • Test one record end-to-end manually (create a test lead, watch it flow through every connected system) and time how long it takes and where it stalls

Step 3 — License utilization audit

For every seat-based tool:

Utilization rate = (seats actively used in last 30 days) ÷ (seats paid for)

  • Utilization below 70% → renegotiate seat count at next renewal
  • Utilization below 40% → candidate for kill or consolidation
  • Cross-check named users against current headcount (departed employees still holding licenses is the single most common waste source)
  • Check for admin/paid seats assigned to service accounts, test accounts, or people who left the company

  • Every field has exactly ONE declared system of record — if two people both say "CRM" and "billing tool" own MRR, that's your leak
  • Spot-check 10 records for each field and confirm the numbers match across systems
  • Any field with no reconciliation process is a confirmed data leak

Step 5 — Redundancy detector

  • List every tool by primary job-to-be-done (scheduling, enrichment, dialing, e-sign, etc.)
  • Flag any job-to-be-done with 2+ active tools assigned to it
  • For each redundant pair, name the one being kept and the reason (feature depth, integration quality, cost, team preference — not just "we've always used both")

Step 6 — Security & access review

  • SSO/SAML enabled on every tool that supports it (flag any that don't and handle customer PII)
  • Admin access list pulled and reviewed — no more than 2–3 admins per tool unless documented
  • Former employees checked against every tool's active user list, not just CRM and email
  • API keys and integration tokens older than 12 months reviewed for rotation

Step 7 — Score and decide

For each tool, assign one status:

  • Keep — utilization >70%, no cheaper alternative, integration healthy
  • Consolidate — overlaps with another tool; migrate data and cancel the weaker one
  • Kill — utilization <40%, no clear owner, or job-to-be-done can be absorbed elsewhere
  • Renegotiate — needed, but seat count/pricing doesn't match actual usage

How to use it

Work through it stage by stage in a single working session with your Sales Ops or RevOps lead, filling the inventory table first — the redundancy and data-leak flags only surface once every tool is on one page.
