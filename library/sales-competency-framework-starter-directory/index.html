Sales Competency Framework Starter Directory

A side-by-side map of the major named sales competency models: MEDDIC/MEDDPICC, Challenger, SPIN, Sandler, Solution Selling, Value Selling, Command of the Message, Strategic Selling, and Consultative Selling: against one shared skill taxonomy, so you can pick the right framework (or right combination) instead of inheriting whatever your last VP liked.

How to use it

Use the coverage map to identify which skill categories your current methodology leaves weak, then either add a second framework to cover the gap or build your own skill-observation criteria directly against the taxonomy instead of a single named methodology.

What's inside

  • The 8-category shared skill taxonomy used to compare every framework on equal terms
  • Full comparison table: origin/author, core mechanism, best-fit sales motion, year introduced
  • Strong / Partial / Weak coverage rating for each framework against all 8 skill categories
  • Framework-by-framework caveats (where each one tends to be misapplied)

  • A one-paragraph plain-English summary of each framework's core mechanism
  • Notes on which frameworks require licensed training vs. which are freely implementable

Every major sales methodology is really answering one of a handful of underlying skill questions. This directory maps the well-known frameworks against a shared 8-category skill taxonomy so you can compare them on equal terms: and see clearly where each one is strong, where it's silent, and where teams tend to misuse it.

The Shared Skill Taxonomy

  1. Discovery & Diagnosis, surfacing the real problem and its business consequence
  2. Qualification & Deal Control: testing budget, authority, timeline, process reality
  3. Value Articulation / Messaging, connecting the offer to a business outcome
  4. Objection Handling & Tension Navigation, working through resistance without caving or arguing
  5. Multi-thread & Stakeholder Management, building relationships beyond one champion
  6. Negotiation, protecting value while reaching agreement
  7. Closing & Momentum, creating and maintaining forward motion
  8. Account Growth / Expansion: post-sale relationship and land-and-expand skill

Caveats: where each one is commonly misapplied

  • MEDDIC/MEDDPICC: treated as a CRM form to fill in after the fact rather than a live qualification conversation: becomes theater, not skill.
  • Challenger: "Take Control" is frequently misread as pushy or scripted; without genuine insight behind it, teach-and-tailor collapses into a canned pitch.
  • SPIN: implication questions get skipped because they're the hardest to construct live: teams default to situation questions, which is just interrogation.
  • Sandler: the "reversing" technique lands as evasive or gimmicky if reps haven't built real rapport first.
  • Solution Selling: works poorly when the buyer already has a defined RFP: it's built for need-creation, not response.
  • Value Selling: ROI models get built once and never revisited per-stakeholder, so the same case is used on a CFO and a user champion.
  • Command of the Message/Sale: requires licensed training and consistent reinforcement: half-adopted, it produces inconsistent messaging that's worse than none.
  • Strategic Selling: Blue Sheets get filled in once at deal kickoff and never updated as buying influences change.
  • Consultative Selling: too vague to train against directly: useful as an ethos, not a standalone curriculum.

Pick-Your-Base Framework Guide

  • Single-stakeholder, transactional, short cycle → Sandler or SPIN as your discovery/qualification spine
  • Multi-stakeholder enterprise, long cycle, committee buying → MEDDPICC + Strategic Selling for qualification and account mapping
  • Status-quo is your main competitor, not another vendor → Challenger for the value/insight layer
  • CFO-scrutinized budget, ROI-driven procurement → Value Selling or Command of the Message for the business-case layer
  • Most real-world stacks combine one qualification framework (MEDDPICC) with one messaging framework (Challenger or Command of the Message), trying to run all of one framework and none of another is the most common failure mode.
